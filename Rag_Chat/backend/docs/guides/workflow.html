3 · 보안 체크포인트 (5단계)

#게이트방어 대상운영 위치
1CORS allowlist외부 도메인 직접 호출settings.CORS_ALLOWED_ORIGINS (env)
2AuditLogMiddleware enter추적 불가 호출모든 mutating 경로
3INBOUND moderation대외비/PII 외부 LLM 송신Admin → ForbiddenWord 운영
4OUTBOUND moderationLLM 응답 누출같은 테이블 (direction=OUTBOUND/BOTH)
5AuditLogMiddleware exitincident 사후 재구성status_code/ip/user 기록

아직 *없는* 게이트 (정직하게)

  • JWT/Role 기반 endpoint 보호 — 데이터 모델만 있고 강제 안 됨. 다음 마일스톤.
  • HTTPS / Redis AUTH / DB 컬럼 암호화 — Stage 2/3.
  • 금지어 단어 경계 정규식 — 현재 substring → false positive 가능.

4 · LLM은 어디에서 호출되는가

사내 (네트워크 안) ✓ SAFE

  • Streamlit · Django · Celery · Postgres · Redis · FAISS/Chroma
  • 원본 질문 · 원본 응답 · ModerationLog · AuditLog · 지식베이스

외부 (Gemini로 송신) ⚠ EXTERNAL

  • 단계 7: sanitized 질문 (embedding 1회)
  • 단계 8: sanitized 질문 + top-k chunk + 시스템 프롬프트 (reasoning + generation 2회)
  • 그 외 — 송신 없음

한 질문당 외부 LLM 호출: 3회 (BLOCK이면 0회)

# Provider 추상화 — 환경변수 한 줄로 외부 LLM 의존 제거

5 · 시나리오별 분기

정상 응답

금지어 없음 → 1~12 통과 → Chat / SearchLog / AuditLog 1행씩, ModerationLog 0행.

MASK 발동

PII 포함 → 단계 5에서 치환 → 마스킹된 텍스트만 LLM에 송신 → 정상 응답 + MASKED 로그.

BLOCK 발동

기밀 코드네임 → 단계 5에서 short-circuit → 403, LLM 호출 0회, BLOCKED 로그.

OUTBOUND BLOCK

LLM이 hallucinate한 기밀어 → 단계 9에서 차단 → 사용자에겐 "표시 불가" 안내 → 운영자 검수.

지식베이스 직접 검색

"S25 담당자 누구?"는 GET /api/v1/knowledge/contacts/?q=S25 1번이면 끝. LLM 호출 0회.

세션 만료

Redis TTL 만료 → 다음 호출 401. Celery beat 5분마다 일괄 정리.
