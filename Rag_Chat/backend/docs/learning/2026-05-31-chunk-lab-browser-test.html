2chunk_lab 진입 + picker 확인

액션

  1. 좌측 사이드바에서 Chunk Lab 또는 🧪 페이지 선택
  2. 제목이 "🧪 Chunk Lab" 보라색 divider 아래 보임
  3. 좌측 사이드바 아래로 스크롤하면 새로 추가된 섹션 "실제 적재" 보임

새 picker 2개 확인:

사이드바 ── 실제 적재 ⚠️ DB·벡터 저장 발생. 좌측 splitter/size 설정은 무시됨... Collection (도메인 분류) [ policy — 사규·정책 ▾ ] ← default Sensitivity (열람 등급) [ internal — 사내 공유 ▾ ] ← default [ 이 파일을 실제 적재 ] (회색 — 파일 업로드 전)
picker 가 안 보이면 페이지 reload (Cmd+Shift+R). Streamlit 캐시 무효화.

3테스트 A — sales 적재

목적: default policy 외 다른 값이 실제 DB 에 박히는지 검증.

액션

  1. 사이드바 "소스" → 파일 업로드 선택
  2. 아무 작은 파일 업로드 (csv / txt / md — 200KB 이하 권장)
    • 예: backend/galaxy_s25_data.csv 같은 기존 영업 데이터
  3. Collection = sales — 영업 데이터 선택
  4. Sensitivity = confidential — 대외비 선택
  5. 이 파일을 실제 적재 (회색 → 보라색 활성)

UI 확인:

위치기대 표시
스피너 "적재 중... (filename.csv)"
결과 헤더 📥 실제 적재 결과 아래 caption: collection=sales · sensitivity=confidential
메트릭 3개 처리됨: 1 · 신규 청크: N · 실패: 0
JSON 상세 [{"filename": "...", "status": "ok", "chunks": N}]
처음엔 OK → 두번째 시도엔 "skipped". 정상. SHA256 동일 → manifest dedup 작동. 테스트 C 참고.

4테스트 B — training 적재

목적: 또 다른 collection 값 검증 + 다중 collection 공존 확인.

액션

  1. "새 파일" 선택 (다른 파일 — 같은 파일이면 dedup 됨)
  2. Collection = training — 학습 자료
  3. Sensitivity = internal — 사내 공유
  4. 이 파일을 실제 적재

5테스트 C — 같은 파일 재적재 (dedup)

목적: SHA256 dedup 으로 같은 파일을 다른 collection 으로 재적재해도 새 청크 안 생기는지 확인.

액션

  1. 테스트 A 에서 올린 같은 파일 재업로드
  2. Collection 을 이번엔 user 로 변경
  3. 이 파일을 실제 적재
지표기대값의미
신규 청크 0 SHA256 동일 → manifest 가 skip
JSON status "skipped" 중복 적재 방지 정상 작동
info 메시지 "모두 dedup skip — 동일 SHA256 manifest 존재." 운영자 가시화
주의: 같은 파일은 가장 먼저 박힌 collection 으로 유지. 나중 picker 변경은 무시됨. 이건 의도적 — manifest 기반 dedup 의 정상 동작. collection 을 바꾸려면 별도 admin UI 필요 (Phase C).

7트러블슈팅

증상원인해결
"invalid credentials" autofill 공백 / 오타 / 백엔드 다운 필드 비우고 직접 타이핑. curl localhost:8000 으로 backend 확인.
chunk_lab 진입 시 "접근 차단" 배너 USER 권한 로그인 로그아웃 후 manager/admin 계정 재로그인.
picker 안 보임 Streamlit 캐시 stale Cmd+Shift+R 하드 리로드. 그래도 안 보이면 streamlit 재시작.
적재 버튼 회색 파일 업로드 모드 아님 OR 파일 미업로드 좌측 "소스" → 파일 업로드 → 파일 선택.
적재 시 "backend 500" Postgres 연결 / 임베딩 API quota backend 로그 확인. Gemini 429 면 OPENROUTER_* 로 provider 스왑.
DB 쿼리 결과에 collection 없음 마이그레이션 미적용 venv/bin/python manage.py migrate knowledge
