S3ACL filter 동작 — P1 vs P3 같은 쿼리 비교

왜. 핵심 검증. 같은 질문 "iPhone 16 카메라" 를 P1 매장 과 P3 본사 가 했을 때 결과 chunk 의 tier 가 달라야 함: P1 는 competitive tier 차단됨 → public/retail 만 옴. P3 는 competitive 보임. 이게 안 되면 ACL 가 무용지물. 
EMBEDDING_PROVIDER=ollama ./venv/bin/python -c "
import os, django
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'triple_chat_pjt.settings')
django.setup()
from chat.providers import provider_manager
from chat.persona import Persona, chroma_filter_for_persona

vs = provider_manager.get_vector_store()
queries = ['iPhone 16 카메라', 'Knox Vault 보안', 'Tab S10 Ultra DeX']

for q in queries:
    print(f'\n=== {q} ===')
    for p in [Persona.P1_RETAIL, Persona.P3_HQ]:
        filt = chroma_filter_for_persona(p)
        hits = vs.similarity_search(q, k=3, filter=filt)
        for h in hits:
            tier = h.metadata.get('audience_tier','?')
            src = h.metadata.get('source_file','?').split('/')[-1]
            print(f'  [{p.value:11}][{tier:11}] {src}: {h.page_content[:50]}')
"
기대 출력 (예시). 
=== iPhone 16 카메라 ===
  [P1_RETAIL  ][public     ] galaxy_handbook.md: ...           # competitive 못 봄
  [P1_RETAIL  ][retail     ] selling_points.md: ...
  [P3_HQ      ][competitive] competitive_handbook.md: iPhone 16 시리즈... # ✓ 정답
  [P3_HQ      ][competitive] competitive_handbook.md: ...

=== Knox Vault 보안 ===
  [P1_RETAIL  ][public     ] ...                # b2b 못 봄
  [P3_HQ      ][b2b        ] b2b_handbook.md: Knox Vault ...
합격 조건: P1 결과의 tier 가 public/retail/carrier 중에만 있으면 OK. competitive/b2b 가 P1 결과에 절대 나오면 안 됨.
P1 결과에 competitive/b2b 가 보이면. → infer_tier 매핑 또는 ChromaSink._to_lc_document 메타 부여 잘못. ingest 재실행: 
EMBEDDING_PROVIDER=ollama ./venv/bin/python manage.py build_vectors --rebuild

S4Persona 별 답변 톤 비교 — 같은 질문 4 페르소나

왜. ACL filter 가 chunk 만 거름. 그 위에 답변 길이·톤 도 페르소나 따라 달라야: P1 매장 = 1~2 문장 친근체. P3 본사 = 표·수치 무제한. P4 외판 = 1 문장 음성친화. 같은 질문 4번 돌려서 출력 길이·톤 차이 눈으로 확인. 
EMBEDDING_PROVIDER=ollama ./venv/bin/python -c "
import os, django
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'triple_chat_pjt.settings')
django.setup()
from chat.pipeline import ModuleContext, PipelineRunner

QUESTION = 'Galaxy S25 Ultra 카메라 어때?'
PERSONAS = ['P1_RETAIL', 'P2_B2B', 'P3_HQ', 'P4_OUTBOUND', None]

for p in PERSONAS:
    print(f'\n========== persona={p} ==========')
    ctx = ModuleContext(
        question=QUESTION,
        session_id='test_session',
        user_id='test_user',
        history=[],
        user_access_level='internal',
        extra={'persona': p},
    )
    pipeline = PipelineRunner([
        {'type': 'retrieve'},
        {'type': 'rerank'},
        {'type': 'reasoning'},
        {'type': 'generation'},
    ])
    try:
        ctx = pipeline.run(ctx)
        print(ctx.response[:400])
    except Exception as e:
        print(f'ERROR: {e}')
" 2>&1 | grep -v "Deprecation\|telemetry\|return Chroma\|return Ollama"
기대 차이.
persona길이톤
P11~2 문장친근체, 즉답
P23~10 문장 + 표/bullet격식, 전문
P3제한없음, 수치 위주데이터 중립
P41 문장음성 친화, 마크다운 없음
None2~3 문장가장 보수적
실제 LLM 출력은 항상 가이드 100% 따르진 않음. 차이가 분명히 보이면 OK. 완벽 일치 안 됨 = LLM 한계 (Ollama gpt-oss 의 instruction following).
4 페르소나 출력이 다 똑같으면. → chat/pipeline/modules.py 의 GenerationModule 이 persona_style 호출 안 함. 코드 확인:

S6EscalationAttempt audit log 확인
