# Project Status (2026-05-18)
영업팀 베타 배포 직전 상태 스냅샷.

> 2026-05-27 갱신 메모: ingest layer Phase 1 skeleton 이 추가됐다.
> 다음 ingest 우선순위는 Celery 비동기 ingest 가 아니라 ingest Phase 2 Manifest
> (`IngestManifest` + SHA256 dedup) 이다. Upload API/외부 트리거가 생기기
> 전까지는 동기 CLI 경로를 유지한다.

## Working Now
- Streamlit UI → Django API → vector search (FAISS/Chroma) → Gemini/Qwen LLM
- **PostgreSQL 16** primary DB (SQLite kept as dev fallback)
- **RBAC 데이터 모델**: `chat.User.role` (USER/MANAGER/ADMIN) + `department` FK
- **knowledge 앱**: Department / Contact / Product 모델 + 검색 API + Django Admin CRUD
- **moderation 앱**: ForbiddenWord / ModerationLog + 다단계 필터(BLOCK/MASK/WARN)가 chat 파이프라인 inbound·outbound 양쪽에 적용 + Django Admin 검수 페이지
- **audit 앱**: `AuditLogMiddleware`가 모든 API 호출 기록
- **헬스체크**: `/api/v1/triple/health/`, `/health/ready/` (DB + Redis + provider)
- **세션 정합성**: Redis TTL ↔ DB `expired_datetime`이 단일 `SESSION_TIMEOUT` 윈도우로 동기화
- **검색 정확도 검증**: chunk_size A/B harness + 영업팀 12문항 평가셋 + 결과 문서화
- **GitHub Actions CI**: lint, Postgres+Redis 통합 테스트, chunk A/B 리포트 artifact, backend+frontend Docker 빌드
- **보안 베이스라인**: DEBUG=0 + 기본 SECRET_KEY 조합 부팅 거부, CORS allowlist env-driven
- Logs: `Chat`, `SearchLog`, `ModerationLog`, `AuditLog` 4종 trace 가능
- 기동: `run_local_fixed.sh` (SQLite dev) / `docker-compose up --build` (Postgres + 전 스택)

## Issues (잔여)
- JWT는 dependencies에 있지만 endpoint protection 미적용 → Phase 1 작업
- Forbidden-word 매칭이 substring (false positive 가능) → 단어 경계 정규식 강화 필요
- 외부 LLM(Gemini/Qwen)에 데이터 송신 → 대외비 등급 상향 시 Ollama/vLLM 전환 필요
- Streaming 미지원 → 응답 체감 속도 개선 여지
- Single node — HA / auto-scale 미설계
- 기존 recursive splitter 기본값은 `chunk_size=1000`; CSV/Excel ingest 는
  Phase 1 이후 row splitter 로 1행 1청크 처리. 텍스트 문서 추가 시
  `chunk_experiment.md` 기준으로 controlled rollout 필요

## Near-term (Phase 1, 1~2주)
1) JWT(simplejwt) endpoint protection 활성화 — Role 기반 권한 데코레이터
2) Streamlit UI에 Knowledge 검색 페이지 추가 (영업팀 시나리오 데모용)
3) 금지어 시드(예시 30개) + 부서/제품 시드 management command
4) controlled rollout: 일부 챗 호출에 `chunk_size=150` 적용 + 응답 품질 모니터링
5) 응답 latency 메트릭 (retrieval + rerank + LLM call) 로깅
6) IngestManifest + SHA256 dedup 으로 Chroma 중복 적재 차단

## Mid-term (Phase 2)
- Ollama PoC — 사내 LLM 대체 경로 검증
- 응답 SSE 스트리밍
- Provider health check + fallback chain (Gemini → Qwen → Ollama)
- ModerationLog retention 정책 + cold storage
- 단어 경계 정규식 + (선택) 다국어 형태소 분석

## Long-term (Phase 3)
- vLLM 멀티 GPU — 외부 LLM 완전 우회
- AuditLog SIEM 송출
- 멀티노드 HA, Redis AUTH/TLS, DB 컬럼 암호화
